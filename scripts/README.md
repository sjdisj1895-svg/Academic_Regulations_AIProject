# 규정 데이터 파이프라인 사용법 (T1 수집 + T2 청킹·벡터DB + T3 검색 API + T4 웹 화면 + T5 품질·운영 + T6~T7 RAG)

## T7. RAG 답변 생성 API — `POST /api/ask`

T6에서 만든 `scripts/rag_engine.py`(검색→컨텍스트 조립→LLM 답변 생성)를 `api_server.py`에
연결한 신규 엔드포인트입니다. 기존 `/api/search`, `/api/chunks`, `/api/regulations`는
전혀 변경하지 않았고, `/api/ask`는 완전히 별도로 추가된 엔드포인트입니다.

### 요청

```
POST /api/ask
Content-Type: application/json

{
  "question": "연구비 감사 관련 행정사무는 어느 부서가 지원해?",
  "top_k": 5,
  "source": ["대학", "산학협력단"],
  "category": ["규정", "지침"]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `question` | ✅ | 질문 (자연어 문장) |
| `top_k` | - | 답변 근거로 사용할 조항 개수 (기본 5) |
| `source` | - | 출처 필터, `/api/search`와 동일 (복수 선택 가능) |
| `category` | - | 카테고리 필터, `/api/search`와 동일 (복수 선택 가능) |

### 응답 (근거 있음)

```json
{
  "query": "연구비 감사 관련 행정사무는 어느 부서가 지원해?",
  "found": true,
  "answer": "연구비 감사 관련 행정사무는 경상국립대학교 산학협력단의 산학감사실이 지원합니다.\n\n근거: [경상국립대학교 산학협력단 감사 지침] 제16조(행정사무의 지원)\n\n[근거 조항]\n- 경상국립대학교 산학협력단 감사 지침 제16조\n...",
  "used_llm": true,
  "results": [ /* /api/search와 동일한 형식(규정 구분·규정명·조항·본문 발췌·담당부서·URL 등) */ ],
  "related_regulations": ["경상국립대학교 산학협력단 감사 지침"],
  "took_ms": 25294.3,
  "suggestions": []
}
```

- `results`/`related_regulations`는 `/api/search` 응답과 완전히 동일한 항목 구조를 그대로 재사용합니다.
- `used_llm`: LLM이 실제로 호출되어 답변을 생성했는지 여부 (관련 조항이 없거나 LLM을 쓸 수
  없으면 `false`).

### 응답 (근거 없음 — 관련 조항 미검색 또는 규정과 무관한 질문)

```json
{
  "query": "오늘 날씨 어때?",
  "found": false,
  "answer": "해당 내용은 규정에서 찾을 수 없습니다.",
  "used_llm": false,
  "results": [],
  "related_regulations": [],
  "took_ms": 49.3,
  "suggestions": ["연구비", "휴학", "장학", "등록금", "성적", "수강신청"]
}
```

- 관련 조항이 0건이면 **LLM을 호출하지 않고** 즉시 위 형식으로 응답합니다(불필요한 LLM 호출
  방지 + 환각 예방, `rag_engine.py`의 T6 설계 그대로).
- `suggestions`: 이런 경우 참고할 만한 추천 검색어(기존 웹 화면의 "결과 없음" 추천 칩과 동일)를 안내합니다.

### 타임아웃 처리 (LLM 응답 지연 대비)

로컬 모델(Qwen2.5-1.5B-Instruct) 기준 답변 생성에 수십 초(실측 25~30초, 최초 1회는 모델
로딩까지 포함해 더 걸릴 수 있음)가 걸릴 수 있어, `/api/ask`는 별도 스레드에서 답변 생성을
수행하고 환경변수 `GNU_RAG_ASK_TIMEOUT`(기본 60초)이 지나면 아래와 같이 **검색 결과만이라도
반환**합니다.

```json
{
  "found": true,
  "answer": "[AI 답변 생성이 60초를 초과해 시간 초과되었습니다. 아래 검색 결과를 참고해주세요.]",
  "used_llm": false,
  "results": [ /* 검색 결과는 정상 반환 (검색 자체는 0.1초 내외로 빠름) */ ],
  ...
}
```

### 실측 테스트 결과

| 질문 | 결과 |
|---|---|
| "연구비 감사 관련 행정사무는 어느 부서가 지원해?" | ✅ `found: true`, "…산학협력단의 산학감사실이 지원…" + `[경상국립대학교 산학협력단 감사 지침] 제16조` 정확히 인용 (25.3초) |
| "휴학 신청은 언제까지 해야 해?" | ✅ `found: true`, "매 학기 수업 일수의 2분의 1이 경과되기 이전에" + `[경상국립대학교 학사관리 규정] 제31조` 정확히 인용 (27.1초) |
| "오늘 날씨 어때?" (규정 무관) | ✅ `found: false`, LLM 호출 없이(`used_llm: false`) 즉시 "해당 내용은 규정에서 찾을 수 없습니다" + 추천 검색어 반환 (0.05초) |
| 기존 `/api/search?q=연구비` | ✅ 변경 없이 그대로 정상 동작 (회귀 확인) |

## T5. 검색 품질 검증 및 운영 체계

> 비전공자 관리자용 안내는 프로젝트 루트의 [`MANUAL.md`](../MANUAL.md)를 참고하세요.
> 아래는 각 스크립트의 상세 사용법입니다.

### ① 검색 품질 자동 평가 — `scripts/evaluate_search.py`

주요 키워드 15개(연구비/휴학/장학/등록금/성적/수강신청/연구윤리/졸업/자연어 질의 등)로
검색을 실행해 **PRD 6.2 성공 지표**(상위 5건 내 노출, 평균 3초 이내 응답)를 자동 판정합니다.

```powershell
python scripts/evaluate_search.py            # API 서버를 통해 평가 (서버가 켜져 있어야 함)
python scripts/evaluate_search.py --direct    # 서버 없이 검색엔진을 직접 호출해 평가
```

**최종 평가 결과** (튜닝 후, `data/search_quality_report.json`에 저장됨):

| 지표 | 결과 | PRD 6.2 목표 | 판정 |
|---|---|---|---|
| 검색 성공률 (상위 5건 내 노출) | 15/15 (100.0%) | 상위 5건 내 노출 | ✅ PASS |
| 평균 응답 시간 | 0.054초 | 평균 3.0초 이내 | ✅ PASS |
| 최대 응답 시간 | 0.096초 | - | ✅ 여유 충분 |

### ② 검색 튜닝 기록 (개선 전/후 비교)

평가 과정에서 **BM25 키워드 검색의 정확도 문제**를 발견해 수정했습니다. (`data/search_tuning_notes.json`)

| 구분 | 내용 |
|---|---|
| 문제 | 자연어 질의 `"휴학하려면 어떻게 해?"`에서, 형태소 분석 없이 완전 일치만 비교하는 BM25가 조사 일부인 한글 1글자(`해`)를 토큰으로 잘못 인식 → 질의의 '해'가 조문 속 `"그 해 3월 1일부터"`(회계연도 조항)의 '해'와 우연히 일치해 **무관한 결과가 1위**로 노출됨 |
| 개선 전 1위 | 경상국립대학교 평생교육원 규정 - 제29조(회계연도) → ❌ 관련 없음 |
| 개선 방법 | `scripts/bm25_lite.py`의 `tokenize()`에 **최소 토큰 길이 2글자 필터** 추가 (숫자는 예외) |
| 개선 후 1위 | 경상국립대학교사범대학부설고등학교 학칙 - 제23조(휴학) → ✅ 정확히 관련 있음 |
| 상위 5건 성공률 | 튜닝 전/후 모두 100% (원래도 5건 안에는 관련 조항이 있었으나, **1위 품질**이 개선됨) |

### ③ 원클릭 데이터 갱신 — `scripts/refresh_all.py`

규정 제·개정 시 관리자가 명령 한 번으로 [수집→청킹→임베딩·벡터DB→품질평가] 전체를 다시 실행합니다.

```powershell
python scripts/refresh_all.py                  # 전체 갱신 (이어받기)
python scripts/refresh_all.py --fresh           # 원문부터 처음부터 다시 수집
python scripts/refresh_all.py --skip-collect --name 인권센터   # 특정 규정만 빠르게 갱신
python scripts/refresh_all.py --skip-eval       # 품질평가 단계 생략(속도 우선)
```

부분 갱신(`--name`) 실행 검증 결과: 청킹 0.3초 + 임베딩·벡터DB 20.8초 + 품질평가 16.6초 = **총 37.6초**로 완료.

### ④ 담당부서·연락처 검수용 목록 — `scripts/export_contacts.py`

```powershell
python scripts/export_contacts.py
```

검색 결과에 표시되는 모든 (출처, 담당부서, 연락처) 조합을 규정 개수와 함께 추출합니다.

| 산출물 | 용도 |
|---|---|
| `data/contacts_for_review.csv` | 엑셀에서 열어 검수(BOM 포함 UTF-8, 한글 정상 표시) |
| `data/contacts_for_review.md` | 이메일·공문 첨부용 표 |

**추출 결과**: 전체 140개 조합 (대학 133개, 산학협력단 7개). 각 행에 검수결과(O/X)·수정할 연락처 칸을 비워두어 총무과·산학연구과가 바로 채워 회신할 수 있게 구성했습니다.

> 📌 참고: 대학 규정은 원본 사이트에 규정별 개별 연락처가 게시되어 있지 않아, 현재
> 사이트 공통 게시 연락처(총무과 055-772-0334)로 표시됩니다. 검수 후 정확한 연락처가
> 확인되면 `data/regulations.json` 갱신 후 `refresh_all.py --skip-collect`로 반영할 수 있습니다.

## T4. 통합 검색 웹 화면

### 실행 방법

T4는 별도 서버가 필요 없습니다. **T3 API 서버(`api_server.py`)가 `web/` 폴더를 함께 서빙**합니다.

```powershell
python -m uvicorn scripts.api_server:app --port 8000
```

브라우저에서 아래 주소로 접속하면 검색 화면이 열립니다.

```
http://127.0.0.1:8000/
```

### 화면 구성 (`web/` 폴더)

| 파일 | 역할 |
|---|---|
| `index.html` | 검색창, 필터, 결과 영역, 미리보기 모달의 뼈대(HTML) |
| `style.css` | 디자인 (연세대 규정집 사이트 스타일을 참고한 카드형 레이아웃, 반응형) |
| `app.js` | 검색 API 호출, 결과 렌더링, 하이라이트, 모달 제어 로직 (순수 JavaScript, 프레임워크 없음) |

### 주요 기능

1. **통합 검색창**: 화면 중앙의 검색창에 단어(`연구비`) 또는 문장(`휴학하려면 어떻게 해?`)을 입력해 검색
2. **필터**: 출처(전체/대학/산학협력단), 카테고리(학칙/규정/지침/산학협력단 각 편) 칩(chip) 버튼으로 선택 → 즉시 재검색
3. **결과 카드**: 카드마다 아래 정보를 표시 (PRD FR-03)
   - 출처 배지(대학=남색/산학협력단=녹색) + 카테고리 배지 + 조항 위치
   - 규정명, 본문 발췌 — **검색어와 일치하는 부분은 노란색 형광펜(`<mark>`)으로 하이라이트**
   - 담당부서·연락처
   - `미리보기` 버튼, `관련 사이트로 이동 ↗` 링크(새 창)
4. **검색 결과 요약**: 카드 목록 위에 "총 N건, 연관 규정 M개(규정명 나열)" 표시 (FR-03 ②)
5. **미리보기 모달**: 카드를 클릭하면 페이지 이동 없이 팝업으로 표시. **"이 조항만" / "규정 전문"** 탭 전환 가능 (FR-05)
6. **결과 없음 안내**: 관련 결과가 없으면 안내 문구와 함께 추천 검색어(연구비/휴학/장학금 등) 칩 제공
7. **로딩 표시**: 검색 요청 중에는 스피너와 "검색 중입니다..." 문구 표시
8. **반응형**: 600px 이하(모바일) 화면에서는 필터가 세로 배치되고 카드 여백이 줄어듦

### 브라우저 자동화(Playwright) 검증 결과

| 항목 | 결과 |
|---|---|
| "연구비" 검색 → 결과 카드 표시 | ✅ 15건 표시 |
| 하이라이트(`<mark>`) 적용 | ✅ 39개 하이라이트 확인 |
| 미리보기 모달(조항/전문 탭) | ✅ 정상 동작, 전문 4,900자 로딩 |
| 관련 사이트로 이동 링크 | ✅ 원본 URL 정상 연결 |
| 출처 필터(산학협력단) | ✅ 산학연구과 연락처로 정상 필터링 |
| 결과 없음 + 추천 검색어 | ✅ 정상 표시 (칩 6개) |
| 모바일(375px) 화면 | ✅ 레이아웃 정상, 카드 15건 표시 |

## T3. 통합 검색 엔진 API 서버

### 준비물 및 실행 방법

```powershell
pip install fastapi uvicorn            # 최초 1회 (T2의 sentence-transformers, chromadb도 필요)

# 프로젝트 폴더 루트에서 실행 (scripts 폴더가 아님)
python -m uvicorn scripts.api_server:app --port 8000

# 개발 중 코드 수정 시 자동 재시작하려면 --reload 옵션 추가
python -m uvicorn scripts.api_server:app --port 8000 --reload
```

서버가 켜지면 브라우저에서 아래 주소로 접속해 자동 생성된 API 문서(Swagger UI)를 확인할 수 있습니다.

```
http://127.0.0.1:8000/docs
```

> ⚠️ 서버를 처음 켤 때 임베딩 모델을 메모리에 올리는 데 30~60초 정도 걸립니다.
> (이 로딩은 서버 기동 시 1회만 실행되며, 이후 모든 검색 요청은 0.1초 내외로 응답합니다.)

### API 엔드포인트 한눈에 보기

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/search` | 규정 통합 검색 (하이브리드: 의미 검색 + 키워드 검색) |
| GET | `/api/filters` | 필터로 쓸 수 있는 출처(source)·카테고리(category) 목록 조회 |
| GET | `/api/chunks/{chunk_id}` | 특정 조항(청크) 상세 조회 — **미리보기**용 |
| GET | `/api/regulations/{reg_id}` | 규정 전문(全文) 조회 — **미리보기(전체)** 및 **관련 사이트로 이동** 연계용 |

### ① 검색 API — `GET /api/search`

**요청 파라미터**

| 파라미터 | 필수 | 설명 | 예시 |
|---|---|---|---|
| `q` | ✅ | 검색어 (단어 또는 자연어 문장) | `연구비`, `휴학하려면 어떻게 해?` |
| `top_k` | - | 반환 개수 (기본 10, 최대 50) | `5` |
| `source` | - | 출처 필터, 복수 선택 가능 | `대학`, `산학협력단` |
| `category` | - | 카테고리 필터, 복수 선택 가능 | `학칙`, `규정`, `지침`, `제2편 학술활동 및 연구지원` 등 |

**요청 예시**

```
GET http://127.0.0.1:8000/api/search?q=연구비&top_k=5
GET http://127.0.0.1:8000/api/search?q=휴학&source=대학&category=학칙
GET http://127.0.0.1:8000/api/search?q=asdf1234xyz        (관련 결과 없음 예시)
```

### ② 하이브리드 검색 방식 요약

1. **의미 검색**: 검색어를 KR-SBERT로 벡터화 → ChromaDB에서 코사인 유사도 상위 후보 조회
2. **키워드 검색**: 순수 파이썬 BM25(`bm25_lite.py`)로 정확한 단어 일치 점수 계산
3. 두 점수를 0~1로 정규화한 뒤 **의미 0.6 : 키워드 0.4** 가중합으로 최종 순위 결정
4. 둘 다 최소 기준(의미 유사도 0.44 미만 & 키워드 일치 0건)에 못 미치면 "관련 없음"으로 판단해 결과에서 제외

### ③ 미리보기 API

```
GET /api/chunks/규정:5667%2325          → 해당 조항(제26조)만 반환
GET /api/regulations/규정:5667          → 규정 전문(全文) 전체 반환 + source_url(관련 사이트로 이동)
```

(⚠️ `chunk_id`에 `#`가 포함되어 있어 URL에 넣을 때는 `%23`으로 인코딩해야 합니다.)

### 성능 확인 결과 (NFR-01: 3초 이내)

실측 결과 평균 **0.05~0.12초**, 최대 0.16초로 목표(3초)를 크게 상회 달성했습니다.

# T1. 규정 데이터 수집 프로그램 사용법

대학(학칙/규정/지침)과 산학협력단 규정을 자동으로 수집하여
`data` 폴더에 텍스트 파일과 통합 목록(`regulations.json`)으로 저장합니다.

## 준비물
- Python 3.10 이상 (별도 외부 라이브러리 설치 불필요 — 표준 라이브러리만 사용)
- 인터넷 연결 (대학 홈페이지 · 국가법령정보센터 접속)

## 실행 방법 (프로젝트 폴더에서)

```powershell
# 전체 수집 (대학 + 산학협력단). 이미 받은 대학 규정은 자동으로 건너뜀(이어받기)
python scripts/collect_all.py

# 규정이 개정되어 처음부터 다시 수집하고 싶을 때
python scripts/collect_all.py --fresh
```

개별 실행도 가능합니다.

```powershell
python scripts/collect_university.py   # 대학 규정만 (학칙 1건 + 규정 약 230건 + 지침 약 134건)
python scripts/collect_foundation.py   # 산학협력단 규정만 (통합 규정집 1권 → 63개 규정으로 분할)
```

## 동작 방식

| 출처 | 방법 |
|---|---|
| 대학 (학칙) | 학칙 페이지 → 국가법령정보센터(law.go.kr) 연동 전문 추출 |
| 대학 (규정/지침) | 게시판 전체 페이지 순회 → 각 게시글의 law.go.kr 링크에서 전문 추출 |
| 산학협력단 | 규정집 게시판 **최신 게시글**의 첨부파일(HWPX) 다운로드 → 목차 파싱 → 규정별 분할 |

## 결과물 (data 폴더)

```
data/
├── regulations.json            ← 전체 규정 통합 목록 (메타데이터)
├── university/
│   ├── 학칙/경상국립대학교 학칙.txt
│   ├── 규정/<규정명>.txt        (약 230개)
│   └── 지침/<지침명>.txt        (약 134개)
├── foundation/<규정명>.txt      (63개)
├── foundation_rulebook.hwpx    ← 산학협력단 규정집 원본 파일
├── progress_university.jsonl   ← 대학 수집 진행 기록 (이어받기용)
├── progress_foundation.json    ← 산학협력단 수집 결과
├── errors_university.json      ← 수집 실패 목록 (비어 있으면 정상)
└── errors_foundation.json
```

### regulations.json 항목 구성 (규정 1건당)
| 필드 | 의미 | 예시 |
|---|---|---|
| source | 출처 | 대학 / 산학협력단 |
| category | 카테고리 | 학칙 / 규정 / 지침 / 제1편 직제 및 간접비 관리 … |
| name | 규정명 | 경상국립대학교 인권센터 규정 |
| department | 소관(관리) 부서 | 교무처>교무과, 산학연구과 등 |
| contact | 담당 연락처 | 총무과 055-772-0334 / 055-772-0211 |
| rule_no / date | 규정번호 / 공포일자 | 제538호 / 2026.08.21 (대학만 제공) |
| source_url | 원본 게시글 URL | '관련 사이트로 이동' 기능에 사용 |
| law_url | 법령정보센터 전문 URL | 대학 규정만 해당 |
| text_file | 저장된 텍스트 파일 경로 | university/규정/….txt |

## 오류가 났을 때
- `data/errors_university.json`, `data/errors_foundation.json`에서 실패한 규정과 원인을 확인하세요.
- 네트워크 일시 오류라면 `python scripts/collect_all.py`를 **다시 실행**하면 실패한 것만 재시도됩니다.
