경상국립대학교의 **대학 규정**(학칙/규정/지침)과 **산학협력단 규정**을 한 곳에서
조·항 단위로 검색하고, 담당부서까지 원스톱으로 확인할 수 있는 AI 검색 시스템입니다.

- 기획 문서: [`PRD.md`](PRD.md) (목적·요구사항·MVP)
- 작업 계획: [`TASKS.md`](TASKS.md) (T1~T5 단계별 계획)
- 구현 프롬프트: [`PROMPTS.md`](PROMPTS.md)
- 파이프라인 실행 방법: [`scripts/README.md`](scripts/README.md)

## 기술 스택 (Tech Stack)

> 원칙: **전부 무료(오픈소스)**, 별도 서버 구매 없이 **로컬 PC에서 실행 가능**,
> 학내 전산 환경(Windows)에서 운영 가능한 것을 기준으로 선정했습니다.

### 전체 구조 한눈에 보기

```
[T1 수집]            [T2 청킹·임베딩]              [T3 검색 API]         [T4 웹 화면]
대학 규정 사이트  ─┐
                   ├→ 텍스트 정리 → 조·항 청킹 → KR-SBERT 임베딩 → ChromaDB
산학협력단 게시판 ─┘   (Python)      (정규식)     (한국어 AI 모델)   (벡터DB)
                                                                      │
                              사용자 ← 웹 브라우저(HTML/JS) ← FastAPI 검색 서버
                                        (T4 예정)              (T3 예정, 하이브리드 검색)
```

### 1. 공통 기반

| 기술 | 버전 | 역할 | 선택 이유 |
|---|---|---|---|
| **Python** | 3.13 | 전체 파이프라인·서버 개발 언어 | AI/데이터 처리 생태계가 가장 풍부하고, 학내 PC에 이미 설치되어 있음. 전 단계(수집→청킹→임베딩→API)를 한 언어로 통일 |
| **Windows (win32)** | - | 운영 환경 | 학내 정보전산처 표준 환경. 모든 도구를 Windows에서 동작 검증 |

### 2. T1 — 데이터 수집 (완료, 사용 중)

| 기술 | 역할 | 선택 이유 |
|---|---|---|
| **Python 표준 라이브러리** (`urllib.request`, `re`, `json`, `zipfile`) | 웹 페이지 요청, HTML 파싱, 데이터 저장 | **외부 라이브러리 설치가 전혀 필요 없어** 어느 PC에서든 즉시 실행 가능. 수집 대상 페이지 구조가 단순해 BeautifulSoup 같은 추가 도구 불필요 |
| **국가법령정보센터(law.go.kr) 연동** | 대학 규정 전문(全文) 추출 | 대학 사이트의 규정 본문이 law.go.kr iframe으로 제공됨을 분석으로 확인 → HWP 파일 변환 없이 **깨끗한 조문 텍스트를 직접 확보** |
| **HWPX 직접 파싱** (`zipfile` + XML 정규식) | 산학협력단 통합 규정집(HWPX) 텍스트 추출 | HWPX는 ZIP+XML 표준 형식이라 한글(HWP) 프로그램이나 유료 변환 도구 **없이** 파이썬만으로 텍스트 추출 가능 |

### 3. T2 — 청킹·임베딩·벡터DB (완료, 사용 중)

| 기술 | 버전 | 역할 | 선택 이유 |
|---|---|---|---|
| **정규식 기반 조문 청킹** (자체 개발, `chunk_rules.py`) | - | 규정을 '제0조 → 제0항(①②③)' 단위로 분할 | 한국 법령 조문은 형식이 일정해(제0조(제목), ①②③ 항) 정규식으로 정확히 분할 가능. 부칙·별표·별지도 별도 구획으로 보존 |
| **sentence-transformers** | 6.0.1 | 임베딩(문장→벡터 변환) 실행 프레임워크 | Hugging Face 표준 임베딩 프레임워크. 무료, 로컬 CPU에서 실행 가능 |
| **KR-SBERT** (`snunlp/KR-SBERT-V40K-klueNLI-augSTS`) | - | **한국어 특화 임베딩 모델** | 서울대 NLP 연구실 공개 모델. 한국어 문장 의미 유사도(STS)에 특화되어 규정 조문 검색에 적합. 무료이며 최초 1회 다운로드 후 **오프라인 실행 가능** (외부로 데이터가 나가지 않아 보안에도 유리) |
| **ChromaDB** | 1.5.9 | 벡터DB (임베딩 저장·유사도 검색) | 오픈소스 무료. **별도 DB 서버 설치 없이** 폴더(`C:\gnu_vectordb`)에 파일로 저장되는 임베디드 방식. 코사인 유사도 검색과 메타데이터 필터(출처/카테고리) 기본 지원 → 소규모 대학 규정(1만 청크 미만)에 충분 |

> ⚠️ 운영 참고: ChromaDB는 **한글이 포함된 폴더 경로**에서 인덱스 로딩 오류가 발생하여
> 영문 경로 `C:\gnu_vectordb`에 저장합니다. (환경변수 `GNU_VECTORDB`로 변경 가능)

### 4. T3 — 검색 엔진 API (완료, 사용 중)

| 기술 | 버전 | 역할 | 선택 이유 |
|---|---|---|---|
| **FastAPI** | 0.141.1 | 검색 REST API 서버 (`scripts/api_server.py`) | 파이썬 대표 경량 웹 프레임워크. 자동 API 문서(Swagger `/docs`) 생성으로 T4 화면 개발·검수 용이. Pydantic 기반 응답 모델로 FR-03 요구 항목(규정 구분·규정명·조항·담당부서 등)을 명확히 정의 |
| **Uvicorn** | 0.52.4 | API 서버 실행기(ASGI) | FastAPI 표준 실행기. 명령 한 줄로 서버 기동, `--reload` 옵션으로 개발 편의성 확보 |
| **BM25 (자체 구현, `scripts/bm25_lite.py`)** | - | 키워드 검색(정확한 단어 매칭) | `rank_bm25` 등 외부 라이브러리 없이 표준 BM25Okapi 수식을 순수 파이썬으로 구현 → 추가 설치 없이 형태소 분석 없는 한글 토큰 매칭만으로도 "연구비" 같은 정확한 단어 검색에 충분한 성능 확보 |
| **하이브리드 검색** (`scripts/search_engine.py`, 자체 구현) | - | 의미 검색 + 키워드 검색 결합 | ChromaDB 벡터 유사도(의미 60%) + BM25 키워드 점수(40%)를 0~1 정규화 후 가중합 → "연구비" 같은 단어 검색과 "휴학하려면 어떻게 해?" 같은 문장 검색을 모두 정확하게 처리 (FR-02). 최소 관련성 기준(의미 유사도 0.44 미만 & 키워드 미일치)으로 무관한 질의는 "결과 없음" 처리 |

### 5. T4 — 웹 화면 (완료, 사용 중)

| 기술 | 역할 | 선택 이유 |
|---|---|---|
| **HTML + CSS + JavaScript (Vanilla)** (`web/index.html`, `style.css`, `app.js`) | 검색 화면(검색창·필터·결과 카드·미리보기 모달) | 별도 빌드 도구(Node.js 등) **설치 없이** FastAPI가 `StaticFiles`로 바로 서빙 → 배포·유지보수가 가장 단순. 연세대 규정집 사이트를 참고한 카드형 UI를 프레임워크 없이 구현 (FR-07) |
| **FastAPI StaticFiles** | 웹 화면 정적 파일 서빙 | T3 API 서버가 `/api/*`는 API로, 나머지 경로는 `web/` 폴더 정적 파일로 서빙 → **서버 하나로 API+화면 통합 운영**, 별도 웹서버(Nginx 등) 불필요 |
| **반응형 CSS (미디어쿼리)** | PC/모바일 대응 | NFR-04 (접근성) 충족. 600px 이하에서 필터·카드 레이아웃 자동 전환 |
| **Playwright** (검증용, 배포에는 불필요) | 실제 Chromium 브라우저로 검색·모달·반응형 자동 검증 | 화면 코드를 실제 브라우저에서 렌더링해 하이라이트·모달·필터·모바일 레이아웃이 의도대로 동작하는지 스크린샷 기반으로 확인 |

## T3 검증 결과 요약

- **"연구비" 검색**: PRD 4.1 예시 형식대로 [규정 구분/규정명/조항·본문/담당부서] 반환 확인

- **미리보기 API**(`/api/chunks`, `/api/regulations`): 조항/전문 정상 반환
- **응답 속도**: 평균 0.05~0.12초 (NFR-01 목표 3초 대비 크게 여유)
- **결과 없음 처리**: 무관한 질의는 관련성 최소 기준 적용해 `total: 0` 정상 응답

## T6 — 웹 화면 디자인 개편 (GNU 브랜드 컬러 적용)

경상국립대학교 공식 홈페이지(gnu.ac.kr)의 실제 CSS를 분석하여, 화면(T4)의 색상·톤을 학교 브랜드에 맞게 다시 입혔습니다.

### 적용한 GNU 브랜드 컬러

| 색상 변수 | 값 | 용도 | GNU 홈페이지 근거 |
|---|---|---|---|
| `--color-primary` | `#091f46` (다크 네이비) | 헤더 베이스, '대학' 출처 배지 | GNU 사이트 강조 텍스트·타이틀 색상 |
| `--color-signature` | `#009edb` (시그니처 블루) | 포인트 컬러, 버튼, 강조, 그림자 | GNU 공식 사이트 전역에서 가장 많이 쓰이는 포인트 컬러 |
| `--color-signature-dark` | `#0071db` (보조 블루) | 버튼 호버, 그라데이션 중간톤 | GNU 사이트 그라데이션·서브 강조 색상 |
| `--color-navy-accent` | `#22499d` | 헤더 그라데이션 중간톤 | GNU 사이트 배너류에서 쓰이는 톤 |
| `--badge-foundation` | `#009e5e` (그린) | '산학협력단' 출처 배지 | GNU 사이트에서도 쓰이는 그린 계열, 대학(네이비)과 명확히 구분 |

### 주요 변경 사항 (`web/style.css`)
- 상단 헤더: 다크 네이비 → 시그니처 블루로 이어지는 **대각선 그라데이션** + 은은한 원형 하이라이트(GNU 사이트 배너 느낌 재현)
- 검색 버튼·필터 칩·포커스 테두리: 시그니처 블루로 통일
- 결과 카드: 호버 시 시그니처 블루 톤의 그림자(`--shadow-hover`)로 부드러운 강조
- 출처 배지: 대학=다크 네이비, 산학협력단=그린으로 명확히 구분
- 하이라이트(형광펜)·모달·모바일 반응형 레이아웃은 T4 구조를 유지하며 색상만 GNU 테마로 교체

- ✅ 모바일(375px) 화면: "휴학" 검색 결과에서 반응형 레이아웃 정상 유지

## 프로젝트 소개 슬라이드 (PPTX)

`MANUAL.md`, `README.md`의 내용을 바탕으로 **경상국립대(GNU) 브랜드 컬러 테마**를 적용한
16장짜리 소개 슬라이드를 만들었습니다.

- 생성 파일: [`AI_규정통합검색시스템_소개.pptx`](AI_규정통합검색시스템_소개.pptx)
- 생성 스크립트: [`scripts/generate_pptx.py`](scripts/generate_pptx.py) (재생성: `python scripts/generate_pptx.py`)
- 구성(16장): 표지 → 추진배경 → 목적/대상 사용자 → 요구사항(검색 예시) → MVP 범위 →
  아키텍처(T1~T5) → 기술 스택①②(수집·청킹·임베딩 / API·화면·운영) → 실제 화면 스크린샷 2장(검색 결과 / 모달·모바일) →
  구현 결과①②③(T1·T2 / T3·T4 / T5 품질검증) → 운영 매뉴얼 요약(MANUAL.md 5단계) → 기대효과 → 마무리
- 사용한 라이브러리: `python-pptx` 1.0.2 (무료, 오프라인 pptx 생성)
- 검증 방법: python-pptx로 재로딩해 슬라이드 수(16)·표·이미지 개수 및 이미지 좌표가 슬라이드 경계
  (13.33×7.5인치) 내에 있는지 자동 점검 완료 (LibreOffice/PowerPoint 미설치 환경이라 프로그램적 검증으로 대체)
